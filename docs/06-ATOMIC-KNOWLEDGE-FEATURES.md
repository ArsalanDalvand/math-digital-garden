# برنامهٔ امکانات پایگاه دانش اتمیک — ECC Gate 1

وضعیت: Gate 1 با پاسخ «بله» تأیید شد؛ امکانات پیاده‌سازی و بررسی نهایی مرورگر تکمیل شدند. کامیتی ایجاد نشده است.

## هدف و محدوده

یادداشت‌های رسمی به یک شبکهٔ دانش قابل پیمایش تبدیل شوند: خواننده مقصد پیوندها را باز کند، ارجاع‌های ورودی و خروجی را ببیند، یادداشت را جست‌وجو کند و از طریق برچسب و فصل به مفاهیم مرتبط برسد. Markdown خام، SHA-256 و جداسازی داده‌های شخصی حفظ می‌شوند. این بسته فقط داده‌های رسمی `canonical_notes` را مصرف می‌کند.

## تصمیم‌های فناوری و شواهد تحقیق

- پوستهٔ آمادهٔ `@astrojs/starlight` با `StarlightPage` برای مسیرهای سفارشی مطالعه: سایدبار، تغییر تم، پیمایش موبایل و فهرست بخش‌ها از اجزای آماده استفاده می‌کنند.
- نسخهٔ مبنای سازگار: Starlight 0.37.0 با peer dependency `astro: ^5.5.0`؛ Astro نصب‌شده 5.18.2 است. آخرین نسخهٔ بررسی‌شدهٔ Starlight 0.42.5 به Astro 7.2.10 و markdown-remark 7.3.0 نیاز دارد و در این بسته استفاده نمی‌شود.
- `remark-wiki-link` برای ساخت AST پیوندهای ویکی و alias با `aliasDivider: '|'`. برای استخراج ارجاعات همان AST استفاده می‌شود؛ parser سفارشی Markdown و regex روی کل متن نوشته نمی‌شود.
- `parseFrontmatter` موجود برای `tags`, `aliases`, `sidebar.order`؛ این متاداده تنها مشتق خواندنی است و منبع Markdown را بازنویسی نمی‌کند.
- جست‌وجوی زنده با کوئری پارامتری SQLAlchemy/PostgreSQL روی عنوان و متن رسمی. جست‌وجوی ساخته‌شده در زمان بیلد جای جست‌وجوی دیتابیس را نمی‌گیرد.
- پیش‌نمایش با رندر مشترک امن و امکانات بومی مرورگر؛ نمایش با hover و focus و دسترسی در لمس بررسی می‌شود.
- `starlight-obsidian` آماده نیز بررسی شد؛ نسخهٔ جاری 0.15.0 به Starlight >=0.41.0 نیاز دارد و برای انتشار vault طراحی شده است. بدون اثبات سازگاری با SSR دیتابیس و نسخه‌های پروژه به آن متکی نمی‌شویم.

مستندات با Context7، ابتدا `library Starlight` و سپس دو درخواست `docs /withastro/starlight` برای صفحات سفارشی و RTL دریافت شدند. peer dependencyها از registry و گزینه‌های parser از README رسمی remark-wiki-link بررسی شدند. API نسخهٔ انتخاب‌شده پیش از ادغام از فایل‌ها و تست‌های همان نسخه بررسی می‌شود.

## ترتیب توسعه و معیار پذیرش

1. **پوستهٔ آمادهٔ مطالعه:** جایگزینی Reader با StarlightPage، حفظ فارسی/RTL و ایزولاسیون KaTeX؛ فهرست بخش‌های قابل کلیک، ناوبری فصل‌ها، تم روشن/تاریک و پیمایش موبایل. مسیرهای `/sample` و `/notes/{slug}` و خطاهای 404/503 باقی می‌مانند.
2. **ویکی‌لینک و نام مستعار:** `[[slug]]`, `[[عنوان فارسی]]`, `[[target|متن نمایشی]]` و aliases در frontmatter به مقصد معتبر نگاشت شوند. نام مبهم یا مقصد ناموجود مشخص شود و به یادداشت اشتباه وصل نشود. پیوند داخل کد و فرمول به ارجاع دانش تبدیل نشود. پیوند به بخش یادداشت با شناسه‌های سازگار فهرست بخش‌ها بررسی می‌شود.
3. **ارتباطات یادداشت:** بخش‌های «ارجاعات به این یادداشت» و «پیوندهای این یادداشت» از همان AST استخراج شوند. لینک تکراری در فهرست ارتباطات یک بار نمایش داده شود؛ حذف یا اصلاح متن رسمی در خواندن بعدی منعکس شود.
4. **جست‌وجو و برچسب:** جست‌وجوی عنوان/متن فارسی با فرم GET، نمایش نتیجه و حالت خالی؛ نمایش برچسب‌ها و پالایش یادداشت‌ها بر اساس برچسب. سایدبار بر اساس کتاب، فصل و ترتیب متاداده ساخته شود.
5. **پیش‌نمایش و تحویل:** پیش‌نمایش مقصد با فرمول و عنوان، بدون اجرای HTML خام؛ تست صفحه‌کلید، لمس و عرض موبایل، ممیزی دسترس‌پذیری و screenshot با agent-browser؛ تست‌های PostgreSQL، بیلد و بررسی تایپ/لینت.

## قرارداد داده و امنیت

- `GET /api/notes` فقط یادداشت‌های رسمی را با ترتیب پایدار و صفحه‌بندی محدودشده به هر درخواست ارائه می‌دهد. پارامترهای `offset`, `limit`, `q` اعتبارسنجی می‌شوند؛ جست‌وجو شرط SQL پارامتری دارد.
- قرارداد `GET /api/notes/{slug}` و فیلدهای فعلی آن حفظ می‌شود. catalogue صفحه‌بندی‌شده برای ساخت نمای مشتق ارتباطات و متاداده استفاده می‌شود و هیچ یادداشتی به علت سقف یک صفحه از شبکه حذف نمی‌شود.
- فهرست روابط و برچسب‌ها دادهٔ مشتق است؛ در بستهٔ اول schema یا جدول جدید لازم نیست. هزینهٔ استخراج شبکه با تعداد یادداشت‌ها رشد می‌کند؛ اگر اندازهٔ catalogue یا زمان پاسخ نامناسب شود، همین نمای مشتق به ایندکس پایدار منتقل می‌شود و Markdown همچنان منبع حقیقت می‌ماند.
- URL مقصد از slug معتبر ساخته می‌شود؛ متن alias و عنوان از مسیر رندر امن می‌گذرد. خام HTML فعال نمی‌شود و `trust: false` برای KaTeX حفظ می‌شود.
- هیچ endpoint دادهٔ شخصی به جست‌وجو یا catalogue عمومی اضافه نمی‌شود. افزودن fork در مرحلهٔ بعد نیازمند کوئری مالکیت جداگانه خواهد بود.

## دامنهٔ تغییر و آزمون

- `frontend/src/lib/markdown.mjs` و تمام callers و تست‌های آن؛ استخراج متاداده، heading و wikiLink از pipeline مشترک.
- Reader، صفحات اصلی/مطالعه، مسیر جست‌وجو و مرور برچسب؛ CSS و تنظیمات Astro/Starlight و lockfile.
- backend API فهرست/جست‌وجو با استفاده از مدل و سشن فعلی؛ تست منفی اعتبارسنجی و عدم نمایش دادهٔ کاربران.
- fixtures چند یادداشت مرتبط با نام فارسی، alias، tags، heading و لینک ناموجود؛ seed غیرتخریبی برای نمایش قابل بررسی.
- `tests/`: ابتدا RED برای رفتار تازه؛ سپس GREEN، PostgreSQL واقعی، رندر/SSR، mypy، ruff، astro check، tsc و build. نتیجهٔ ابزار مرورگر و screenshotها ثبت می‌شوند.

## مسئولیت و کارهای خارج از این بسته

برنامه‌ریزی، معماری، توسعهٔ اصلی و یکپارچه‌سازی با ایجنت اصلی است. Gemini فقط ممیزی جانبی/بازبینی مستقل انجام می‌دهد و برای ممیزی اولیه با sandbox فقط‌خواندنی فراخوانی شد؛ خروجی نهایی در مهلت تعیین‌شده دریافت نشد و تأیید مستقل محسوب نمی‌شود.

گراف سراسری تعاملی، transclusion بازگشتی، ویرایشگر، احراز هویت و sync مستقیم vault در این بسته ساخته نمی‌شوند. پس از عملیاتی‌شدن لینک و backlinks، گراف محلی با کتابخانهٔ آماده می‌تواند در بستهٔ بعد اضافه شود.

طبق orch-pipeline، پیش از کدنویسی این برنامه در Gate 1 تأیید می‌شود و پیش از کامیت نیز Gate 2 برقرار است. در مرحلهٔ تحقیق dependency یا کد عملیاتی تغییر نکرد؛ نصب و توسعه پس از تأیید انجام شد.


## شواهد اجرای توسعه — ۲۰۲۶/۱۰/۰۸

- RED: تست تازهٔ catalogue پاسخ ۴۰۴ گرفت؛ تست شبکه به‌دلیل نبود `buildKnowledge` شکست خورد. تست صفحه‌بندی به‌دلیل نبود fetchCatalogue شکست خورد. تست seed مرتبط به‌دلیل نبود تابع مربوطه شکست خورد.
- RED برای مرزهای خطا: پیوند به heading دارای پرانتز با ID فهرست بخش‌ها مطابقت نداشت؛ پیش‌نمایش ID تکراری داشت؛ query نامعتبر پیش از validation سشن دیتابیس می‌ساخت. همه با تست‌های مربوطه اصلاح شدند.
- GREEN: ۲۰ تست Python با PostgreSQL 16 + pgvector واقعی، بدون skip، گذشتند؛ پوشش branch-aware بک‌اند ۹۱٪ است. Ruff و mypy گذشتند.
- GREEN: ۱۰ تست واحد frontend و ۸ تست SSR از خروجی واقعی بیلد گذشتند. جست‌وجوی فارسی، برچسب، حالات خالی/خطا، XSS عنوان و پیش‌نمایش، و روابط بررسی شدند. Astro check و TypeScript خطایی ندارند و بیلد موفق است.
- Starlight 0.37 در Head متن title را HTML در نظر می‌گیرد؛ override کوچک Head فقط title را به‌عنوان متن رندر می‌کند. تست `</title><img onerror=...>` از فرار عنوان جلوگیری می‌کند؛ meta attributes از escaping خود Astro استفاده می‌کنند.
- RED مرورگر: Tailwind reset عنوان را ۱۶px کرده بود و کنتراست گزینهٔ فعال سایدبار پایین بود. integration فعال Tailwind، که caller فعالی نداشت، حذف شد؛ عنوان دسکتاپ ۴۲px و موبایل ۳۵px شد و ممیزی axe صفر violation داد.
- Starlight 0.37 وضعیت aria-expanded را روی host منو می‌نویسد؛ wrapper کوچک، همان وضعیت را روی دکمهٔ اصلی منعکس می‌کند. موتور منو بازنویسی نشده است.
- RED مرورگر: Escape از داخل پیش‌نمایش با انتقال فوکوس دوباره آن را باز می‌کرد. ترتیب انتقال فوکوس/بستن اصلاح شد و گشودن خودکار به فوکوس قابل‌مشاهده محدود شد تا لمس با رفتار native details کار کند.
- Gemini برای ممیزی جانبی فقط‌خواندنی فراخوانی شد و فایل‌ها/سناریوهایی را بررسی کرد؛ اجرای ۲۴۰ثانیه‌ای به timeout رسید. درخواست دومِ بدون ابزار نیز در ۱۲۰ثانیه گزارش نهایی نداد. بنابراین این کار تأیید مستقل نهایی Gemini محسوب نمی‌شود؛ توسعه و بازبینی امنیتی/آزمون‌ها با ایجنت اصلی انجام شدند.

## محدودیت‌های باقی‌مانده

- خواندن تمام catalogue و رندر شبکه در هر درخواست برای پایگاه دانش کوچک مناسب است؛ آزمون بارِ مجموعهٔ بزرگ انجام نشده است. رشد زمان پاسخ، محرک جایگزینی با ایندکس مشتق پایدار است.
- stock Pagefind غیرفعال است؛ جست‌وجوی فعلی به دیتابیس فعال نیاز دارد. صفحهٔ `/sample` همچنان مستقل است.
- مجموعهٔ static docs در Starlight عمداً خالی است و هشدار می‌دهد؛ صفحات سفارشی SSR به دیتابیس متصل‌اند. دامنهٔ انتشار مشخص نیست و sitemap تولید نمی‌شود.
- گراف، transclusion، editor/auth/forks/RAG/sync همچنان خارج از این بسته‌اند. تغییر دادهٔ رسمی یا ورود به دادهٔ شخصی اضافه نشده است.
- Gate 2 طبق orch-pipeline فقط پیش از کامیت نیاز به تأیید دارد؛ این بسته هنوز کامیت نشده است.


## نتیجهٔ بررسی نهایی مرورگر

با session اختصاصی agent-browser و سرور واقعی Node متصل به FastAPI/PostgreSQL بررسی شد:

- آزمون‌های `tests/browser/knowledge-check.js`, `menu-check.js`, `preview-check.js` سبز شدند؛ عنوان و فونت، RTL، ایزولاسیون LTR ریاضی، نبود ID تکراری، نبود overflow در ۳۹۰px، بازکردن منو و Escape، hover پیش‌نمایش و Escape از داخل آن بررسی شدند.
- `tap` واقعی پیش‌نمایش را باز و بسته کرد؛ `tap` منوی موبایل وضعیت `aria-expanded=true` را روی دکمه ثبت کرد.
- جست‌وجوی «مجموعه» در فرم GET نتیجه داد؛ انتخاب برچسب «مبانی» تنها «مجموعه‌ها» را نمایش داد. ناوبری ویکی‌لینک به `/notes/sets#تعریف-مجموعه` با صفحهٔ مقصد واقعی بررسی شد.
- تعویض تم روشن/تاریک کار کرد. axe-core در تم تیره و موبایل صفر violation گزارش داد. موارد incomplete شامل نمادهای غیرمتنی KaTeX برای contrast و aria-expanded روی host بدون نقشِ Starlight بودند؛ وضعیت مؤثر دکمه با تست جداگانه بررسی شد و رنگ فرمول‌ها در screenshot و محاسبهٔ contrast مرورگر بررسی شد.
