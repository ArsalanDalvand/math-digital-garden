# تصمیم تأییدشده Dify و تحویل مرحله‌ای به Codex

وضعیت: تصمیم کاربر تأیید شده؛ اجرای اتصال هنوز تأیید نشده است.
تاریخ: 2026-10-09

## مرجع تصمیم

این سند در تعارض‌های مربوط به AI بر معماری قدیمی 01 و نقشه راه قدیمی 03 مقدم است. PRD مرجع رفتار محصول، کد و اجرای تست مرجع وضعیت واقعی‌اند. گزارش‌های 05-AI-PLATFORM-RESEARCH، 06-AI-SIDEBAR-SOURCE-AUDIT و 07-DIFY-PLUGINS-RESEARCH شواهد تحقیق‌اند، نه ادعای نصب. شماره‌های همسان در نام اسناد مختلف به معنای یکسان‌بودن سند نیست؛ نام کامل را بخوانید.

کاربر حذف یا جایگزینی کد اضافه را مجاز دانسته است. حفظ موتور AI قدیمی الزام نیست؛ ولی این اجازه شامل حذف داده کاربران، volume، والت خصوصی، اسرار یا بازنویسی تاریخچه Git نیست. ابتدا مسیرهای متأثر و علت حذف ثبت شوند. بازنویسی کل سایت صرفاً به خاطر تغییر موتور AI موجه نیست. پیش از حذف کد untracked نسخه بازیابیِ فقط سورس و تنظیمات غیرمحرمانه تهیه شود؛ .env، کلیدها، DB و داده خصوصی وارد checkpoint نشوند.

## تصمیم معماری

- تجربه اصلی: پنل چت/ایجنت کنار صفحه جزوه همین سایت؛ کاربر وارد رابط Dify یا DeepTutor نمی‌شود.
- Dify موتور جریان AI است؛ ساخت موتور موازی PydanticAI/LangGraph یا نصب DeepTutor در این مسیر لازم نیست.
- حساب‌ها، نسخه رسمی/خصوصی، مجوزها، استناد نسخه‌دار و تأیید ویرایش در سایت باقی می‌مانند.
- بک‌اند معتبر سایت context مجاز را می‌سازد و با کلید سروری Dify درخواست می‌دهد. user از نشست تعیین می‌شود، نه از ادعای مرورگر.
- گفتگو و runهای Dify به مالک سایت نگاشت می‌شوند. endpointهای workflow/run بدون کنترل مالکیت proxy نشوند.
- مدل‌ها از 9Router با افزونه رسمی OpenAI API Compatible؛ هیچ credential در سورس، DSL، گزارش، prompt یا فرانت‌اند قرار نگیرد. قابلیت endpointها جداگانه آزموده شود.
- حفظ UI فعلی در صورت مناسب‌بودن؛ assistant-ui اختیاری پس از سنجش هزینه adapter/React، نه الزام بازنویسی Astro.
- منابع RAG فعلی قابل استفاده‌اند، ولی index دوم موازی بدون نیاز نسازید. DB سایت منبع حقیقت است؛ Dify knowledge مالک نسخه‌های شخصی نیست.
- انتخاب embedding و ابعاد براساس provider واقعی؛ vector(1536) موجود قرارداد همیشگی نیست. تغییر آن فقط با migration و reindex قابل‌بازگشت، بدون حذف داده اصلی.

## مکمل‌های مصوب به‌صورت مرحله‌ای

شروع: Dify Chatflow، provider رسمی OpenAI-compatible، پنل سایت و تست رگرسیون Promptfoo.
Maths رسمی فقط محاسبه عددی با numexpr است. SymPy برای مرحله ابزارهای نمادین پشت API محدود، همراه فرض دامنه، timeout و محدودیت حافظه؛ اجرای Python آزاد یا parse ورودی نامطمئن بدون محافظ ممنوع.
Langfuse تنها اگر امکانات لاگ Dify کافی نبود؛ retention و حذف داده خصوصی لازم است.
MinerU یا Docling فقط هنگام نیاز PDF، نه هر دو؛ فارسی/فرمول/مجوز نسخه واقعی بررسی شود.
Podcast Generator برای مرحله صوت؛ TTS از مسیر مصوب و با آزمون فارسی/هزینه.
وب‌گردی، datasource GitHub، Sync والت، MCP مستقل و اجرای کد آزاد جزو شروع نیستند. قابلیت‌های موجود خارج از AI را این کار حذف یا گسترش نمی‌دهد.

## قرارداد نسخه اول

ورودی منطقی: سؤال، شناسه یادداشت، نوع نسخه رسمی/خصوصی، نسخه مورد انتظار و متن انتخاب‌شده/موقعیت آن. بک‌اند مجوز، نسخه و انطباق selection را بررسی و متن واقعی مجاز را بازیابی می‌کند؛ متن بازیابی‌شده داده است نه دستور ابزار.
خروجی منطقی: رویداد متن، منبع، پایان یا خطا؛ شناسه گفتگو تحت مالکیت کاربر. نام endpoint و schema نهایی بعد از بررسی کد موجود تثبیت و مستند شوند.
ارجاع: note_id، revision/hash و block/section مجاز با نگاشت سروری. Markdown ورودی به تنهایی citation معتبر ایجاد نمی‌کند. منبع نامعتبر/قدیمی نباید به عنوان شاهد معتبر نمایش داده شود.
تغییر صفحه در همان conversation باید context جدید را منتقل کند. فیلدهای ورودی Chatflow مانند selected_text نام‌های تعریف‌شده برنامه‌اند، نه فیلد جادویی Dify.
پاسخ فقط با تأیید کاربر به نسخه شخصی وارد می‌شود؛ انتشار رسمی همیشه در چرخه بازبینی مؤلف است.
قطع Dify نباید خواندن، حساب، ویرایش و ذخیره جزوه را مختل کند. خطای واضح و timeout لازم است؛ fallback پنهان به مدل یا provider دیگر ممنوع.

## برش‌های اجرایی و دروازه‌ها

### A — بررسی مبنا و برنامه تغییر کوچک
- وضعیت Git و فایل‌های untracked را ثبت کنید؛ شاخه، سرویس‌ها و داده موجود را بدون تغییر بررسی کنید. در مشاهده مستندسازی، فایل‌های متعدد untracked بودند؛ این وضعیت را زنده تأیید کنید.
- قرارداد UI/API موجود و تست baseline را ثبت کنید. خطای قبلی را از regression جدا کنید.
- در docs/09-DIFY-IMPLEMENTATION-STATUS.md مسیر دقیق فایل‌های create/modify/delete، دلیل حذف، قرارداد context/SSE و فرمان‌های واقعی تست را بنویسید.
- از طراحی معماری جدید یا ساخت دوباره فازهای قبلی خودداری کنید؛ حذف کد اضافه با حفظ بازیابی مجاز است.

### B — اولین برش عمودی (هدف همین نوبت Codex)
- ابتدا تست قرمز برای احراز هویت، context رسمی/خصوصی، رد conversation متعلق به دیگری، رد نسخه/selection نامعتبر و خطای provider.
- اتصال Dify در backend و حفظ/تطبیق SSE فعلی؛ قرارداد مدل از UI جدا بماند.
- یک Chatflow حداقلی قابل export برای توضیح متن انتخابی و راهنمایی مرحله‌ای؛ DSL با نسخه واقعی Dify import شود. credential داخل فایل نباشد.
- تنظیمات Dify اختیاری و fail-closed؛ .env.example فقط نام متغیر و placeholder غیرواقعی. هیچ سرویس موجودی متوقف یا volume حذف نشود.
- تست‌های واحد با fake مجاز و واضح‌اند؛ fake شاهد اجرای Dify واقعی نیست.
- اتصال واقعی: سایت → Dify → 9Router → پاسخ در پنل همان جزوه. اگر سرویس/کلید در دسترس نیست، کارهای مستقل تکمیل و smoke واقعی صریحاً BLOCKED ثبت شود؛ موفقیت جعل نشود.
- نمایش فارسی/LaTeX و تغییر صفحه، قطع/لغو استریم، عدم ذخیره خودکار متن تولیدی و عدم نمایش داده کاربر دیگر بررسی شود.
- در پایان برش B توقف و گزارش برای بازبینی؛ مراحل بعد خودکار شروع نشوند.

### C — منابع و ذخیره پاسخ
بازیابی نسخه‌دار، citation قابل کلیک و مجاز، رد شاهد نامعتبر، ذخیره پاسخ با تأیید در نسخه شخصی و تعارض نسخه. تست دو حساب شامل فایل، citation، گفتگو، run و cache؛ تست قطع provider؛ سپس smoke واقعی.

### D — ارزیابی و ابزار محدود
Promptfoo از طریق API سایت، با موارد فارسی دارای شاهد/بدون شاهد، فرض پنهان، متن خصوصی و راهنمایی بدون لو دادن پاسخ. تست‌های قطعی امنیت جدا از داوری LLM. افزودن SymPy فقط بعد از تثبیت قرارداد ابزار و محدودیت اجرا. نصب مکمل‌های دیگر در برش‌های جدا با نیاز واقعی.

## تعریف تحویل Codex

گزارش شامل فایل‌های تغییرکرده/حذف‌شده و علت، تست‌های اجراشده و exit code، baseline مقابل regression، شاهد smoke واقعی یا دلیل BLOCKED، محل DSL و نسخه Dify/plugin، روش اجرا/بازگشت بدون اسرار و مرحله پیشنهادی بعد است. گزارش implementation با تأیید کاربر یا قبولی production یکسان نیست. commit/push یا اجرای destructive بدون درخواست جدا لازم نیست.

## حدود این تحویل

این نوبت تنها اسناد و دستور شروع آماده شده‌اند. وجود کد در پروژه مشاهده شد؛ کیفیت و اجرای آن در این نوبت تأیید نشده است. Dify نصب یا متصل نشده و هیچ کد محصولی حذف نشده است.
