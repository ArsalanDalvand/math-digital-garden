# برنامهٔ اجرایی فاز 1 — زیرساخت و مطالعه

## محدوده و PRD

مرجع اجرایی این مرحله، پرامپت فاز 1 سند `03-IMPLEMENTATION-ROADMAP-AND-AGENT-TASKS.md` است. فازبندی کلان PRD با نقشه‌راه اجرایی یکسان نیست: احراز هویت، انشعاب شخصی و ویرایشگر در فاز 2 اجرایی باقی می‌مانند. در این مرحله هیچ API نوشتن عمومی، JWT، ویرایشگر، RAG یا جدول انشعاب ساخته نمی‌شود.

### معیارهای محصول

- خواننده، یادداشت فارسی شامل فرمول درون‌متنی، فرمول چندخطی و برهان تاشو را می‌خواند.
- API فقط نسخهٔ رسمی را با Markdown خام، بدون تبدیل ذخیره‌سازی، برمی‌گرداند.
- جداول `users` و `canonical_notes` و افزونهٔ `vector` با میگریشن قابل اجرا ایجاد می‌شوند.
- بیلد Astro 5، تایپ‌ها، تست‌های واحد/یکپارچگی و مسیر مطالعه در مرورگر بررسی می‌شوند.

## معماری

- `backend/app/`: FastAPI، تنظیمات از محیط، SQLAlchemy 2.0 async و asyncpg؛ مدیریت سشن با dependency.
- `backend/migrations/`: Alembic async و میگریشن اولیهٔ PostgreSQL.
- `compose.yaml`: PostgreSQL 16 با pgvector، volume پایدار و healthcheck؛ اتصال فقط روی localhost.
- `frontend/`: Astro 5 با Node adapter. حالت SSR برای یادداشت‌های دیتابیس و prerender برای مسیر نمونهٔ مستقل از دیتابیس. `hybrid` در Astro 5 حذف شده؛ قابلیت ترکیبی با `output: server` و `prerender: true` ارائه می‌شود.
- Tailwind CSS، فونت محلی Vazirmatn، remark-math و rehype-katex. افزونهٔ آمادهٔ کال‌اوت Obsidian؛ از parser سفارشی و ادیتور خودساخته استفاده نمی‌شود.
- `custom.css`: RTL متن، `direction: ltr !important` و `unicode-bidi: isolate` برای KaTeX و کد، اسکرول مستقل فرمول بلوکی.

## قراردادهای داده

ساختار جداول مطابق `01-ARCHITECTURE-AND-TECH-STACK.md` است. شناسه‌ها UUID، زمان‌ها timezone-aware با خروجی ISO 8601 مانند `2026-10-08T12:00:00Z`، `current_content` متن خام UTF-8 و `current_hash` برابر SHA-256 بایت‌های UTF-8 همان متن است. `role` فقط `student | author | admin`؛ `slug` یکتا است. گذرواژهٔ خام هیچ‌جا ذخیره یا از API ارسال نمی‌شود.

### API فقط‌خواندنی

- `GET /health`: زنده بودن پردازش بدون وابستگی به دیتابیس، پاسخ `{"status":"ok"}`.
- `GET /api/notes/{slug}`: پاسخ JSON شامل `id`, `slug`, `title`, `book_slug`, `chapter_slug`, `relative_path`, `current_content`, `current_hash`, `updated_at` برای یادداشت رسمی.
- slug نامعتبر: `422`؛ یادداشت ناموجود: `404`؛ دیتابیس غیرقابل دسترس: `503` با پیام عمومی، بدون نمایش URL یا اعتبارنامه.
- هیچ اندپوینت عمومی برای فهرست کاربران، password_hash، ایجاد یا تغییر یادداشت وجود ندارد.
- `DATABASE_URL` از محیط بارگذاری می‌شود؛ `.env` هرگز در Git نیست. `.env.example` فقط نام متغیرها با مقدار خالی دارد.

5. بازبینی ECC و رفع ایرادهای مهم پیش از تحویل.

## ترتیب اجرای کارها (ECC Gate 1)

برنامه توسط کاربر تأیید شد و پیاده‌سازی طبق چرخهٔ RED/GREEN انجام شده است؛ تأیید نهایی فاز هنوز باز است.

### مسئولیت‌ها

- ایجنت اصلی: برنامه‌ریزی ECC، تعیین قراردادها، معماری، توسعهٔ مسیرهای اصلی، چرخهٔ TDD، یکپارچه‌سازی و اعتبارسنجی نهایی.
- Gemini: کارهای جانبی مستقل مانند ممیزی سازگاری مستندات، بررسی کامل بودن معیارهای پذیرش و بازبینی مستقل تغییرات. برنامه‌ریزی و توسعهٔ بخش‌های سنگین به آن واگذار نمی‌شود؛ یافته‌های آن پیش از اعمال توسط ایجنت اصلی بررسی می‌شوند.
- درخواست‌های مستندات Context7 با `proxychains4 npx ctx7@latest ...` اجرا می‌شوند؛ دریافت مستندات Codex از این مسیر با کد خروجی صفر تأیید شده است.

1. **اولین مسیر مطالعه:** ابتدا تست‌های مردود برای سلامت API و رندر قضیهٔ نمونه؛ سپس اسکلت FastAPI و Astro، صفحهٔ نمونهٔ مستقل از دیتابیس، KaTeX، فونت محلی و کال‌اوت برهان تاشو. معیار پذیرش: صفحهٔ فارسی با فرمول چندخطی و برهان قابل کنترل با صفحه‌کلید، بیلد و تست موفق.
2. **مطالعه از دیتابیس:** ابتدا تست مدل‌ها، حفظ دقیق Markdown و پاسخ‌های API؛ سپس Compose، مدل‌های `users` و `canonical_notes`، میگریشن Alembic و اتصال مسیر مطالعه به API رسمی. معیار پذیرش: اجرای میگریشن روی PostgreSQL 16/pgvector، پاسخ‌های 404/422/503 و عدم افشای اطلاعات کاربر یا اتصال دیتابیس.
3. **تحویل قابل اجرا:** تست مرورگر برای جهت متن و فرمول، برهان تاشو و عرض موبایل؛ بررسی تایپ‌ها، لینت، پوشش تست و بازبینی کد و امنیت؛ ثبت دستورهای اجرا و شواهد RED/GREEN. پیش از کامیت، خلاصهٔ تغییرات و پیام‌های پیشنهادی برای ECC Gate 2 ارائه می‌شوند.

دامنهٔ فایل‌ها: `backend/app/`، `backend/migrations/`، `frontend/`، `tests/`، پیکربندی وابستگی‌ها و ابزارهای بررسی، `compose.yaml`، `.env.example`، `.gitignore`، `README.md` و همین سند. نمونهٔ Markdown مشترک برای تست حفظ متن و نمایش استفاده می‌شود. رابط یا دادهٔ عملیاتی موجودی برای مهاجرت وجود ندارد؛ فایل‌های مستندات و تغییرات فعلی حفظ می‌شوند.

پیش‌نیازها: بررسی مستندات جاری کتابخانه‌ها با Context7 پیش از پیاده‌سازی؛ فراهم کردن Python 3.12 مطابق معماری (نسخهٔ پیش‌فرض محیط 3.13 است) و ابزار مدیریت بستهٔ فرانت‌اند. وجود دستور Docker به‌تنهایی به معنی آماده بودن daemon نیست؛ اجرای واقعی دیتابیس در گام دوم بررسی می‌شود.

وضعیت واگذاری: ابزار `spawn_agent` شناسهٔ پیش‌فرض `ag/gemini-3.8-flash-high` را نمی‌پذیرد. واگذاری بررسی مستقل اسناد از طریق `codex_tui.create_thread` با همین شناسه انجام شد؛ وظیفهٔ `01a11c2b-848f-7783-ae9c-4c5470a0d63d` پیام و اجرای واقعی دستور بررسی مخزن دارد. تنظیمات سراسری تغییر نکردند. وظیفه پس از خروج از محدودهٔ ممیزی خواندنی آرشیو شد. فایل‌های زیرساخت ساخته‌شده توسط آن بازبینی و اصلاح شدند؛ از جمله حذف CORS نامحدود و اعتبارنامهٔ ثابت Compose. در ادامه، ایجنت اصلی مالک توسعه و بررسی‌ها بود. وضعیت نهایی وظیفه `interrupted` است و هیچ ویرایش موازی فعالی از آن باقی نمانده؛ نتیجهٔ آن به‌عنوان تأیید مستقل تحویل محسوب نمی‌شود.

FastAPI مطابق تصمیم معماری حفظ شد؛ مهاجرت به Django در محدودهٔ تأییدشده نیست. احراز هویت، ویرایشگر، RAG، همگام‌سازی گیت و GeoGebra تعاملی ساخته نشدند؛ بلوک GeoGebra در این فاز به‌صورت کد خواندنی حفظ می‌شود.

### موارد باز و محدودیت محیط

- `docker compose ps` با `permission denied` برای `/var/run/docker.sock` رد شد؛ میگریشن آنلاین، یکتایی‌ها و رفت‌وبرگشت واقعی روی PostgreSQL هنوز اثبات نشده‌اند. تست آمادهٔ `tests/test_postgres.py` با `TEST_DATABASE_URL` روی دیتابیس اختصاصی `_test` قابل اجراست.
- اجرای سرور Node با `listen EPERM` برای `127.0.0.1:4321` رد شد. ابزار مرورگر نیز تأیید می‌خواست و سیاست `never` اجرای آن را رد کرد؛ بررسی بصری فونت، جهت فرمول، صفحه‌کلید، عرض موبایل و screenshot انجام نشده است.
- Context7 با proxychains در بخش قبلی جلسه موفق بود؛ پس از محدودشدن شبکه، درخواست‌های Astro و Starlight با `fetch failed` رد شدند. این گزارش دریافت مستندات جدید آن‌ها را ادعا نمی‌کند.
- نصب مجدد آفلاین pnpm به‌دلیل نبود metadata لازم برای بررسی سیاست‌های وابستگی تمام نشد؛ وابستگی‌های از قبل موجود استفاده شدند و manifest/lockfile تطبیق داده شدند. نصب تمیز و ممیزی آنلاین هنوز باز هستند.
- پیام اصلاح مأموریت Gemini توسط بررسی خودکار ابزار رد شد: ارسال پیام نیازمند تأیید بود و سیاست محیط `never` است. آرشیو وظیفه موفق بود؛ بازبینی مستقل نهایی Gemini ادعا نمی‌شود.
- هیچ کامیت یا push انجام نشده است. Gate 2 مربوط به کامیت پس از ارائهٔ تغییرات و تأیید کاربر است؛ `.git` نیز در محیط فعلی فقط‌خواندنی است.

این مرحله «پیاده‌سازی آمادهٔ بررسی» است و تا اجرای آزمون واقعی دیتابیس و بررسی مرورگر، فاز اول طبق DoD کامل اعلام نمی‌شود.


### بررسی تکمیلی مسیر مطالعه و agent-browser

به درخواست کاربر مهارت `agent-browser` خوانده شد و راهنمای نسخهٔ نصب‌شده با `agent-browser skills get core` و `--full` دریافت شد. `agent-browser --version` نسخهٔ 0.37.1 را نشان داد؛ `doctor --offline --quick` وجود Chrome را تأیید کرد. اجرای session اختصاصی روی نمونهٔ ساخته‌شده ابتدا با `Failed to create socket directory: Read-only file system` رد شد. با انتقال مسیر موقت سوکت به `/tmp` نیز daemon بالا نیامد؛ لاگ آن `Failed to bind stream server: Operation not permitted` و `Failed to bind socket: Operation not permitted` را نشان داد. مرورگر یا screenshot موفق ادعا نمی‌شود.

برای آزمون عملکرد SSR بدون مرورگر و بدون بازکردن سوکت، از `App.render(Request)` آمادهٔ Astro روی خروجی واقعی بیلد استفاده شد. پنج تست مسیر موفق، یادداشت ناموجود، قطع API، payload نامعتبر و slug نامعتبر همگی پاس شدند. این تست‌ها جای بررسی بصری و دیتابیس واقعی را نمی‌گیرند.
