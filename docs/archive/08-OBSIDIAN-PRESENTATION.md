# امکانات نمایشی Obsidian با Astro/Starlight

وضعیت: برنامه توسط کاربر تأیید و پیاده‌سازی شد؛ جایگزین دامنهٔ گستردهٔ سند 07. commit انجام نشده است.

## هدف و انتخاب آماده

درخواست کاربر: نمایش ارتباط یادداشت‌ها در گراف قابل تنظیم و نمایش پیش‌نمایش با قرارگرفتن اشاره‌گر روی لینک نوت. استفاده از اکوسیستم Astro/Starlight در اولویت است. کار اصلی و تصمیم‌های معماری با ایجنت اصلی؛ بازبینی جانبی با Gemini.

تحقیق 2026-10-08 با Context7 از طریق proxychains4، npm registry و سورس tarball انجام شد:

- [starlight-site-graph](https://github.com/fevol/starlight-site-graph) نسخهٔ 0.5.0، MIT، peerهای Astro >=5.5.0 و Starlight >=0.33.0 دارد؛ نسخه‌های نصب‌شدهٔ 5.18.2 و 0.37.0 این محدودیت را برآورده می‌کنند. سازگاری اجرایی باید در build و مرورگر تأیید شود.
- کامپوننت exportشدهٔ `Graph` مستقیماً `slug`، `config` و `sitemap` می‌گیرد. از همان خروجی canonical موجود `buildKnowledge`، عنوان، links، backlinks و tags به قالب ورودی این کامپوننت داده می‌شود. sitemap استاتیک زمان build برای نوت‌های دیتابیس منبع حقیقت نخواهد بود.
- تنظیمات آماده شامل fullscreen، depth، reset-zoom، render-arrows و settings است؛ موتور D3/Pixi و کنترل‌های خود بسته استفاده می‌شوند. الگوریتم گراف یا پنل تنظیمات دیگری نوشته نمی‌شود.
- [starlight-theme-obsidian](https://github.com/fevol/starlight-theme-obsidian) نسخهٔ 0.4.1 از نظر peer با پروژه سازگار است، اما تغییر تم برای افزودن دو قابلیت لازم نیست. در سورس بررسی‌شده قابلیت popup نوت یافت نشد؛ این بسته به‌عنوان گزینهٔ ظاهری ثبت می‌شود و در این برش نصب نمی‌شود.
- `starlight-obsidian` عمدتاً برای انتشار vault است؛ آخرین نسخهٔ بررسی‌شده 0.15.0 به Starlight >=0.41.0 نیاز دارد. مسیر انتشار جدید و ارتقای عمده برای این دو قابلیت ضرورت ندارد.

## ترتیب کار

1. تست قرمز زیر `tests/` برای نگاشت نودها و ارتباطات canonical به ورودی Graph، لینک‌های Unicode و عدم درج متن خام یا اطلاعات شخصی. سپس استفادهٔ مستقیم از کامپوننت آماده در صفحهٔ نوت؛ گراف محلی و حالت سراسری/تمام‌صفحه با کنترل‌های خود بسته و تنظیم اولیهٔ قابل تغییر در config پروژه. دسترسی با صفحه‌کلید و فهرست ارتباطات موجود حفظ می‌شود.
2. تست قرمز برای پیش‌نمایش لینک‌های داخلی در متن نوت؛ استفادهٔ مجدد از `previewHtml` امن فعلی و قابلیت Popover مرورگر با اتصال حداقلی. hover و focus پیش‌نمایش را باز می‌کنند؛ Escape می‌بندد؛ در موبایل دکمهٔ پیش‌نمایش مستقل از لینک، مسیر ورود به نوت را حفظ می‌کند. موقعیت popup، خروج از محدودهٔ صفحه و عدم تکرار id آزموده می‌شوند. پکیج اضافی فقط اگر قابلیت بومی برای موقعیت‌دهی کافی نباشد، پس از بررسی مستندات انتخاب می‌شود.
3. تست سبز واحد و SSR، Astro check، TypeScript و build؛ بررسی واقعی با agent-browser در فارسی/RTL، فرمول‌های KaTeX، دو تم و موبایل. Gemini فقط بازبینی جانبی انجام می‌دهد؛ نتیجهٔ آن با شواهد اصلی تطبیق داده می‌شود.

## محل تغییر و حدود

`frontend/package.json` و lockfile برای بستهٔ گراف؛ component گراف و popup؛ renderer مشترک تنها به اندازهٔ اتصال لینک‌ها؛ صفحهٔ نوت و styles؛ تست‌های واحد/SSR/browser و شواهد مستندات. callers دیگر `buildKnowledge` و `Reader` باید بررسی شوند. raw Markdown و hashها تغییری نمی‌کنند؛ migration و API جدید لازم نیست. اطلاعات عمومی تنها از catalogue رسمی موجود می‌آید.

Canvas، Bases، importer، موتور انتشار Quartz، کامنت و ارتقای عمده خارج از این برنامه‌اند. سازگاری peer تضمین اجرای SSR نیست؛ اولین برش باید آن را اثبات کند. واکشی catalogue کامل در هر صفحه محدودیت موجود است و این کار آن را برطرف نمی‌کند.

Gate 1: تأیید این برنامه قبل از کد عملیاتی؛ Gate 2: تأیید جداگانه قبل از commit.

## نتیجهٔ اجرا

گراف از خود `starlight-site-graph` استفاده می‌کند؛ مسیر نودها و edgeها مطابق قرارداد واقعی بسته بدون slash ابتدایی نگاشت می‌شوند. تست مرورگر وجود واقعی نوت‌ها در گراف، جداسازی گراف محلی/سراسری، تغییر عمق، حفظ فوکوس کنترل بازسازی‌شده، تنظیم نیروی دافعه و ورود/خروج تمام‌صفحه را بررسی می‌کند.

بسته در مرورگر به Node APIهای micromatch نیاز داشت. `vite-plugin-node-polyfills` تنها برای path/util/process در bundle مرورگر ثبت شد؛ SSR APIهای واقعی Node را حفظ می‌کند. micromatch که قبلاً dependency بسته بود، برای resolve شدن optimizeDeps در pnpm مستقیماً ثبت شد. در dev نیز رندر و تست واقعی گراف بررسی شد.

پیش‌نمایش با Popover بومی مرورگر و رندر امن موجود اضافه شد؛ mouse، keyboard، Escape و دکمهٔ موبایل بررسی شدند. برای جلوگیری از چندبار ارسال کل نوت‌های بلند، preview سه بلوک نخست را نشان می‌دهد؛ مطالعهٔ کامل از لینک مقصد ممکن است. در مرورگرهای فاقد Popover، لینک اصلی و preview قدیمی در فهرست ارتباطات باقی می‌مانند.

نمونهٔ واقعی کاربر نشان داد رندر کامل catalogue در هر درخواست کند است. با `lru-cache` آماده یک snapshot canonical در هر process نگهداری می‌شود؛ کل دادهٔ ورودی در key شرکت می‌کند و تغییر متن/metadata cache را باطل می‌کند. ترتیب catalogue هنگام جایگزینی نوت حفظ شده و جست‌وجو صرفاً metadata را می‌خواند. گذر استخراج heading نیز دیگر KaTeX را دوباره اجرا نمی‌کند.

TypeScript کد `src/` و declarationهای Astro را بررسی می‌کند. config با اجرای واقعی Astro و build اعتبارسنجی می‌شود؛ source خام TypeScript خود بستهٔ third-party در بررسی `tsc` کد برنامه وارد نمی‌شود. import declaration رسمی Starlight برای locals حفظ شد.

شواهد RED/GREEN و مرورگر در `docs/verification/` قرار می‌گیرند. پوشش گزارش‌شده مربوط به ماژول‌های JavaScript مشترک است؛ تعامل Astro/DOM با SSR و agent-browser بررسی می‌شود. بازبینی جانبی Gemini اجرا شد؛ ادعای آن دربارهٔ bypass شدن cache توسط forceFetch با مستندات رسمی و تست identity/زمان درخواست رد شد.
