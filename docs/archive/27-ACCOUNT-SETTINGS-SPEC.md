# Account profile and preferences

Source: local Docmost account-settings, account-preferences, account-avatar and account-name-form components. Keep the garden shell and existing Persian theme. Omit two-step authentication and device management.

Authenticated users edit their display name, email (current password required), password (current password required, revoke other sessions), avatar and persisted reading/theme preferences. Identity includes role; no endpoint accepts a user ID. Avatar input is bounded fully decoded PNG/JPEG/WebP; Pillow reencodes metadata-free PNG. No SVG, remote image fetch, database migration execution, or live-data mutation.

Contract: GET /api/account; PATCH /api/account/profile {full_name}; PATCH /api/account/email {email,current_password}; PATCH /api/account/password {current_password,password}; PUT /api/account/avatar (raw PNG/JPEG/WebP <=512 KiB, <=512 pixels each side); DELETE /api/account/avatar; GET /api/account/avatar (self only); PATCH /api/account/preferences {theme,size,leading,width,focus,default_mode,fixed_toolbar}. Writes retain existing session and CSRF/origin checks. Responses exclude password hashes and image bytes. Preferences retain garden-theme and garden-reading browser compatibility.

Paths: new account_settings router and 0004 migration, User columns, AccountMenu, /settings/account/profile, /settings/account/preferences (legacy paths redirect), shared account settings script and styles. Root integrates router in main.py. Tests use isolated SQLite users/auth_sessions tables, real session dependency and CSRF checks; assert persistence, ownership, validation, password/session behavior and avatar rejection. Existing auth/me remains compatible.

Acceptance: saved name/avatar appears in account menu after reload; profile/email/password errors are visible; preferences apply and survive reload; anonymous and cross-origin writes fail; no role escalation or foreign user access.
