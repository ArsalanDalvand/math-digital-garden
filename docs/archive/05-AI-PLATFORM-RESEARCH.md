# پژوهش انتخاب پلتفرم AI برای Math Digital Garden

تاریخ مشاهده: 2026-10-09 UTC
وضعیت: پیشنهاد پژوهشی؛ نه انتخاب مصوب، نه نتیجهٔ نصب، تست امنیت یا benchmark.

## خلاصه تصمیم

دو مسیر متفاوت را نباید یکی گرفت:
- کمترین ساخت قابلیت آموزشی و استفاده از محصول آماده: DeepTutor نامزد اول آزمون است.
- حفظ سایت اختصاصی و افزودن موتور جریان‌های AI از طریق API: Dify نامزد اول آزمون است.
- Langflow جایگزین MIT برای مسیر دوم و AnythingLLM گزینهٔ محدودتر برای چت روی جزوات هستند.

در منابع بررسی‌شده محصولی که تمام نیازهای اختصاصی ما (Markdown آبسیدین، متن رسمی، فورک خصوصی، بازبینی مؤلف، استناد به نسخه، فارسی و ریاضی) را بدون اتصال یا توسعه پوشش دهد تأیید نشد. نبود تأیید، به معنی ناممکن بودن نیست.

## روش و حدود شواهد

۱۲ مخزن بررسی شد. متادیتای ستاره، وضعیت آرشیو و آخرین push مستقیماً از GitHub REST API دریافت شد. README و LICENSE از raw.githubusercontent.com خوانده شد؛ برای دو نامزد، مستندات امنیت/چشم‌انداز و درخت سورس نیز بررسی شد. چند جستجوی وب برای کشف پروژه‌ها و یافتن مستندات رسمی به کار رفت. ابزار استخراج وب برای GitHub خطای private/internal network داد؛ دریافت مستقیم فایل خام جایگزین شد.

سطوح شواهد:
- متادیتا: مشاهده مستقیم API در تاریخ بالا.
- امکانات: اعلام مستندات پروژه، نه اجرای مستقل.
- DeepTutor isolation: وجود فایل‌های پیاده‌سازی و تست و خواندن یک نمونه تست تأیید شد؛ تست‌ها اجرا نشدند.
- تناسب و اولویت: استنتاج پژوهشی برای این پروژه.
- کیفیت فارسی، صحت ریاضی، هزینه، ظرفیت و ایزولاسیون واقعی: هنوز آزموده نشده.

## ۱. DeepTutor: نزدیک‌ترین نامزد به محصول آموزشی

README فعلی قابلیت‌های Chat، Ask Questions، Quiz، Solve، Mastery Path، Immersive Reading، Practice، Book، Co-Writer و Knowledge Center را معرفی می‌کند. رابط با Next.js و بک‌اند Python/FastAPI است. بنابراین پذیرش کامل محصول می‌تواند جای بخشی از معماری اختصاصی قبلی را بگیرد، نه اینکه فقط یک کتابخانه به Astro اضافه شود.

شواهد مشخص:
- Reading: سند کنار گفتگو، ارجاع، اقدام روی متن انتخاب‌شده و ذخیره یادداشت.
- Co-Writer: Markdown با ذخیره خودکار، پیش‌نمایش KaTeX، ویرایش محدوده انتخاب‌شده و Undo.
- Book: محتوای تولیدی با بلوک‌های متن، آزمون، فلش‌کارت، گراف و یادداشت؛ پیشرفت و Page Chat خصوصی برای خوانندگان کتاب مشترک طبق README.
- Knowledge Center: بازیابی چندموتوره، اتصال Obsidian و منابع GitHub؛ نباید همه موتورهای اختیاری را هم‌زمان نصب کرد.
- چندکاربری اختیاری و grantهای کتاب، KB، مدل و ابزار؛ auth پیش‌فرض غیرفعال است.
- نمونه کد tests/multi_user/test_resource_isolation.py مسیرهای کتاب و session دو کاربر را مقایسه می‌کند. این شاهد وجود تست است، نه قبولی تست یا ممیزی جامع.

شکاف‌های مهم:
1. کتاب تولیدشده از منابع با نسخه رسمیِ بدون تغییر جزوه یکسان نیست. جزوه رسمی نباید بی‌اجازه بازنویسی مولد شود.
2. Co-Writer طبق README می‌تواند پس از درخواست، متن انتخاب‌شده را مستقیم جایگزین کند؛ الزام ما به پیش‌نمایش diff و تأیید پیش از اعمال نیازمند تطبیق است.
3. یادگیری خصوصی روی کتاب مشترک معادل فورک متنی خصوصی با نسخه مبدأ و پیشنهاد merge نیست؛ گردش کامل ما تأیید نشد.
4. کیفیت RTL، فرمول، wikilink و callout آبسیدین آزمایش نشده است.
5. API داخلی، SDK و CLI وجود دارند؛ پایداری قرارداد headless، SSO و نگاشت هویت سایت نیاز به بررسی نسخه منتخب دارد.
6. exec، MCP و دسترسی مستقیم فایل باید برای دانشجو پیش‌فرض غیرفعال باشند؛ والت خصوصی واقعی نباید mount شود.
7. وجود export Markdown، round-trip کامل را تضمین نمی‌کند.

حکم: پیش از ساخت از صفر، یک نمونه محدود از این محصول را آزمایش کنیم. اگر با توسعه کم به مدل رسمی/خصوصی برسد، اولویت استفاده از محصول آماده با آن تأمین می‌شود.

## ۲. Dify: موتور AI برای رابط اختصاصی

README جریان بصری، RAG، مدیریت مدل، ابزار و observability و API را ارائه می‌کند. مستندات API می‌گوید کلید در بک‌اند نگه داشته شود و یک کلید برنامه می‌تواند برای کاربران نهایی متعدد استفاده شود؛ کلید مدیریتی نباید به مرورگر برسد.

آماده: اجرای جریان، مدل‌ها، retrieval، ابزار، چت و streaming بر اساس API انتخابی.
با پیکربندی: توضیح ساده، راهنمایی مرحله‌ای، خلاصه و تولید ساختاریافته سؤال/کارت.
نیازمند کار محصول: صفحه مرور کارت، نمره/پیشرفت، ذخیره نسخه شخصی، diff، مجوزها و ارجاع به نسخه.

دو مسیر بازیابی:
- جزوات رسمی را داخل Knowledge ایندکس کنیم و نگاشت source/version را نگه داریم.
- بازیابی در سایت و ارسال context مجاز، یا External Knowledge API با مجوز محدود.
نباید از روز اول دو خط لوله موازی و مستقل برای یک محتوا ساخته شود.

پیشنهاد MVP: اطلاعات شخصی فقط از بک‌اند احرازهویت‌شده وارد context همان درخواست شود؛ retrieval عمومی از جزوات رسمی آغاز شود. توسعه retrieval خصوصی چندمرحله‌ای بعد از تست مجوز.

مجوز: متن فعلی tenant را workspace تعریف می‌کند؛ استفاده backend تجاری مجاز توصیف شده، ولی بهره‌برداری چندworkspace مستقل و branding نیازمند انطباق با شروط است. چند دانشجو را خودکار چند tenant Dify فرض نکنیم. این جمع‌بندی حقوقی قطعی نیست.

## ۳. گزینه‌های دیگر

### Langflow
MIT، سازنده بصری، componentهای Python و API/MCP. برای ترکیب ابزارها خوب است؛ سامانه مرور و تمرین آماده نیست. مستندات امنیت تأکید می‌کند auto-login غیرفعال، secret مستقل و CORS محدود شود؛ پورت مدیریت نباید عمومی باشد.

### AnythingLLM
MIT، چندکاربری و مجوز در Docker، workspace، سند، استناد، ابزار و Developer API. مناسب اولین نسخه «از جزوه سؤال بپرس». widget عمومی را برای منابع خصوصی دانشجو به کار نبریم؛ ارتباط احرازهویت‌شده بک‌اند لازم است. ساخت تجربه آموزشی مرحله‌ای و مرور کارت همچنان باقی می‌ماند.

### Open Notebook
MIT، API-first، منابع چندرسانه‌ای، notes، transformations و پادکست. VISION.md صریحاً single-user first است. راهنمای امنیت یک رمز مشترک بدون حساب/role را توصیف می‌کند. reverse proxy ورود اضافه می‌کند، اما مالکیت داده داخل برنامه را خودکار جدا نمی‌کند. برای سایت چنددانشجویی نیاز به جداسازی instance یا توسعه دامنه‌دار دارد.

### SurfSense
خروجی‌های study guide، quiz، flashcards و podcast جذاب‌اند، اما README فعلی دسکتاپ را مسیر پشتیبانی اصلی و نسخه Docker وب را community-supported می‌داند. سرویس میزبانی‌شده در حال بازنشستگی است. LICENSE برخلاف ساده‌سازی badge، بخش proprietary با BSL دارد. امکانات دسکتاپ را به نسخه وب تعمیم ندهیم.

### RAGFlow
پردازش سند، chunking، citations، retrieval و API/agent. برای PDFهای دشوار جذاب؛ برای مبدأ Markdown ما ضرورت فوری ندارد. README پیکربندی شروع پیشنهادی ۴ هسته، ۱۶GB RAM و ۵۰GB فضای آزاد را ذکر می‌کند؛ این benchmark یا ظرفیت تضمین‌شده نیست.

### LibreChat / Open WebUI
پنل چت چندکاربره، مدل‌ها، ابزارها و تعامل فایل آماده‌اند. LibreChat دارای MIT و API مدیریت Agent بتا در README فعلی است؛ Open WebUI شروط branding دارد. اگر پنل AI مجزا هدف باشد ارزشمندند؛ برای محیط خواندن کتاب و fork رسمی/خصوصی همچنان اتصال و UI خاص لازم است.

### Onyx / FastGPT / Flowise
Onyx برای دانش سازمانی و connectorها مناسب است؛ هسته MIT ولی ویژگی‌های سازمانی باید با EE تطبیق داده شوند. FastGPT ابزار RAG/workflow مشابه Dify با مجوز شرط‌دار است؛ در این بررسی مزیت تعیین‌کننده برای نیاز ما مشاهده نشد، نه اینکه بی‌ارزش باشد. Flowise طبق API و README آرشیوی است؛ اولویت انتخاب جدید ندارد.

## پیشنهاد مرحله‌بندی

### آزمایش تصمیم: فقط DeepTutor و Dify

با یک مجموعه مشترک جزوه فارسی، یک مدل و embedding مشترک، و دو حساب جدا مقایسه شوند. Dify پشت رابط کوچک سایت؛ DeepTutor ابتدا با رابط خودش. این مقایسه هزینه استفاده مجدد را روشن می‌کند. لازم نیست ۱۲ محصول نصب شوند.

دروازه‌های اجباری:
1. نمایش و بازیابی فرمول، قضیه، برهان، لینک و فارسی.
2. سوال از خط انتخاب‌شده و ارجاع قابل بازکردن به نسخه منبع.
3. پاسخ «منبع کافی نیست» برای سوال بی‌پشتوانه.
4. راهنمایی بدون افشای جواب کامل تا درخواست صریح.
5. دو حساب با شناسه‌های دستکاری‌شده در API، فایل، citation، session، cache و export.
6. پیشنهاد ویرایش فقط با تأیید؛ جلوگیری از overwrite هنگام تغییر هم‌زمان.
7. تغییر/حذف منبع و حذف اثر آن از بازیابی جدید.
8. قطع مدل، restart، لغو درخواست و سقف مصرف بدون قفل مطالعه.
9. خروجی Markdown و export قابل بازیابی.
10. اجرای همه فراخوانی‌های مدل از endpoint مصوب؛ سازگاری 9Router در chat، ابزار، streaming و embedding جدا سنجیده شود.

ثبت نتیجه هر آزمون: نسخه/commit و تنظیمات، ورودی ثابت، خروجی، pass/fail، زمان پاسخ، مصرف ثبت‌شده، فایل‌های اتصال، محدودیت باقی‌مانده. آزمون امنیت و صحت منابع شرط عبور است؛ با امتیاز زیبایی UI جبران نمی‌شود. هزینه و زمان از اجرای واقعی اندازه‌گیری شوند.

### MVP بعد از انتخاب
- خواندن جزوه و پرسش از متن انتخاب‌شده؛ پاسخ مستند و راهنمایی مرحله‌ای؛ ذخیره پاسخ مفید در فضای شخصی.
- سپس آزمون/فلش‌کارت و بررسی راه‌حل و ابزارهای محدود ریاضی.
- سپس صوت، PDF دشوار، شخصی‌سازی و قابلیت‌های بلندمدت.
- در مرحله اول multi-agent پیچیده، graph RAG و اجرای کد آزاد ضروری نیستند.
