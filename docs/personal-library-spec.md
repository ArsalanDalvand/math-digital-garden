# Personal library acceptance specification

Private folder/note UUID collection is separate from canonical notes and forks. Existing Markdown is untouched. Owner filters precede pagination and all edits; folders persist when empty. Moves reject cycles and invalid/non-owned parents. Trash hides descendants through ancestor checks; restore preserves the original location and fails while an ancestor is trashed.

Notes retain raw Markdown, SHA256 optimistic concurrency and immutable revisions. A publication is an explicit title/content snapshot. Private edits never modify it; switching private revokes links. Sharing publishes only the single snapshot, never parents, descendants, references or attachments. Unlisted links use random revocable tokens. Attachments are bounded database bytes with owner-only downloads and attachment disposition. Comments and watchers require authenticated owner/public/token access. Watch updates compare visible publication hashes; no email. Verification is admin-only and tied to the published hash.

API: `/api/library/items` list/create; `/items/{id}` read/patch; `/trash`, `/restore`, `/history`, `/history/{revision}/restore`, `/attachments`, `/publication`, `/comments`, `/watch`; `/public/{id}`, `/shared/{token}`, `/attachments/{id}`, `/watching`. Mutations reuse session authentication and CSRF guard. Lists bounded to 100. Create `{kind:folder|note,title,parent_id?,content?}`; save `{content,expected_hash}`; move/rename `{parent_id?,title?}`; publish `{visibility:private|unlisted|public}`; upload `{filename,content_base64}`. Public DTO excludes ownership and ancestry. No permissions UI, exports, AI, or live migrations.

Acceptance: two-user HTTP tests exercise IDOR, pagination, cycles/trash/restore, conflict and history, snapshot privacy/revocation, attachment boundaries, comments/watch access and admin verification. Dedicated isolated PostgreSQL HTTP tests cover this collection; production PostgreSQL migration remains an explicit deployment step. Gemini unavailable; inspected local Docmost page/history/trash, attachment, comment, share and watcher services as behavior references.

## Security audit and migration preservation

Found and fixed malformed Unicode share tokens causing `compare_digest(str,str)` to raise; byte comparisons now return 404 for unauthorized Unicode tokens. Library JSON receives `Cache-Control: no-store`. Document edits, publication and uploads lock the document row; tree moves serialize on the owner row so concurrent valid-looking moves cannot form a cycle. Verification also locks the published row. Watch fingerprints include visible title plus content hash, so draft title changes remain private and explicit title-only publication marks an update.

Additional HTTP checks cover rotated-token watch/favorite/comment denial, ancestor-trash blocking public discovery/history/attachments, draft title/body absence from snapshots, control/path traversal filenames, own comment edit/delete, and title-only watch updates. Public DTO deliberately includes no parent/owner/user account fields; verification exposes only admin UUID/time. Comments expose author UUID, never email, password, avatar or account preferences. Existing canonical/fork APIs are unchanged.
