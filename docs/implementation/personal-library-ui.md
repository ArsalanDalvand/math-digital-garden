# Personal library UI contract

Private document routes reuse WorkspaceNote; page actions await garden:flush-note before copying Markdown, moving, trashing, publication and revision actions. The event resolves {content,hash} and rejects on save failure. Public/shared routes render raw snapshot Markdown with renderMarkdown, without the private knowledge graph. SSR forwards cookies only for the owner route and sets no-store; unlisted/public responses prohibit indexing.

PersonalLibrary.astro supplies a lazy folder tree, 50 items per request with explicit continuation and identity-generation checks. /library provides paginated owner notes, folder creation/navigation, favorites, watched updates and trash restoration. Root Reader hosts [data-note-more] and [data-note-extra-actions]; LibraryActions moves its controls there. Public pages use a native details fallback. The document page mounts WorkspaceNote with slug and libraryId.

Action dialogs request 100 records at a time using explicit continuation, capped at 1000 loaded records with a visible limit notice. Comment replies appear with their parent when that parent is among loaded records. LibraryActions implements actual backend calls for favorite, watch/read status, persisted reading width, title/move/trash, history comparison and hash-checked restore, explicit one-page publication, attachment upload/download/delete, threaded page comments and administrator verification. Publication is an explicit saved snapshot; it includes only the selected note and current attachments. New attachments require publication again. Source Markdown remains unchanged by language and display preferences.

Acceptance: owner navigation cannot show a previous identity's pending folder/list response; publication can be revoked; stale revision restore returns conflict; comment text is inserted using textContent; attachment filenames and comment text never use innerHTML. Root verification must cover actual rendered controls and authenticated backend authorization; synthetic frontend checks do not prove authorization.
